AEGIS P2P

Operation Guide & OpSec Manual — Resilience & Anonymity

SECTION 1: SECURITY PRINCIPLES & STARTUP

Zero-Persistence of Secrets: AEGIS never stores your master_key, session keys, or chat history on disk. All this sensitive data resides exclusively in RAM. An encrypted file (vault.json) is used only to store a cryptographic salt and an HMAC verifier, which cannot be used to recover your keys.

Unlocking & Security Codes: On first launch, you set a strong PIN (6+ characters). This PIN is used to derive your master_key via HKDF-SHA256. You can configure a second PIN (decoy mode) that opens a fake dashboard.

  • Anti-Capture Protection (FLAG_SECURE): Prevents screenshots, video recordings, and masks the app preview in the Android task switcher.
  • Auto-Lock: After 1 minute of inactivity, RAM is purged and the app closes.

SECTION 2: KEY EXCHANGE & P2P CONNECTION

P2P Identity Derivation: Your network identity is an ed25519 public key, deterministically derived from your master_key via HKDF-SHA256. It is therefore unique, ephemeral (changes if the PIN changes), and requires no additional storage.

Establishing a connection:

  • Face-to-face: Tap MY QR CODE. Your contact scans the code with SCAN A QR CODE to initiate the E2EE handshake.
  • Remote: Tap COPY MY KEY and transmit it via a secondary channel. The recipient pastes it into the "Recipient's Public Key" field and taps CONNECT PEER.

SECTION 3: NETWORK TRANSPORT SWITCH

AEGIS can route your messages through three encrypted transports, selectable manually or automatically:

  • Tor (Max Anonymity): Uses an integrated Tor client (Arti) to connect to the Tor network and access .onion addresses. Masks your IP address and bypasses censorship. (Higher latency).
  • Direct (P2P): Direct TCP/UDP connection between peers via their IP address (with STUN for discovery). Offers the best throughput but exposes your IP to the peer (if you are not behind Tor).
  • Offline / Local (LAN / Bluetooth): Works without Internet via Wi-Fi Direct or BLE Mesh for physical meetings.
  • Hybrid Mode (Auto): Automatically switches between Tor, Wi-Fi Direct, and BLE Mesh based on network availability and your security policy.

SECTION 4: STEGANOGRAPHY & EMERGENCY MODULE

  • Hide a key in text: Hide a key or phrase in the Steganography module and tap HIDE KEY IN A POEM.
  • Extract a key: Paste the received steganographic text and tap EXTRACT KEY FROM TEXT to load the recipient.
  • Immediate Destruction: In the emergency panel, tap IMMEDIATE RAM DESTRUCTION (KILL SWITCH) to purge memory without leaving a trace.

SECTION 5: SECURE MEDIA PROCESSING (ZERO-DISK)

Zero-Disk Ingestion: All photos, videos, and documents you import into AEGIS are processed exclusively in RAM via the aegis_ingest_file_zero_disk() module. No temporary files are created on the device's storage. The content is destroyed when the app closes.

RAM Security (Polymorphic RAM): Buffers containing your media in RAM are protected by a dynamic XOR mask (at random offset) and a "dual rail" structure (two copies with integrity canaries). This prevents direct memory reading (cold boot, RAM dump) and detects any tampering (bit-flip).

  • Anti-PRNU: Images captured by the camera (CameraX) are processed to mitigate PRNU (Photo Response Non-Uniformity) patterns. This is a unique sensor fingerprint that could identify the phone during forensic analysis.
  • EXIF Stripping: All metadata (geolocation, device model, timestamp) is removed from images before sharing.
  • "Blind" Viewer: Content is displayed via an isolated VRAM surface (BlindView). The preview is masked in the task switcher, and screenshots are blocked by global FLAG_SECURE.
  • Secure Sealing (Optional): If you choose to persist media to disk (via aegis_seal_ram_to_disk()), the stream is first converted from YUV420 to RGBA, then encoded to JPEG (quality 85) entirely in RAM, before being written. No raw files are left on disk.
